# Team release authorization

A named operator couples assignment with deployment authority and conflicts with team ownership. A static users/teams list duplicates GitHub's access control and requires organization-specific configuration. Effective repository write access is the existing source of authority. Optional user assignees route work without granting access. Legacy named-operator policy must remain restricted until an explicit reviewed migration.

No team memberships, repository roles, cloud permissions or deployment gates change. There are no remaining design questions for this scope.
